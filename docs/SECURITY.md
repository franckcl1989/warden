# Warden 0.1.0 安全设计

状态：`APPROVED_BASELINE`

## 1. 安全边界

Warden 持有能关闭服务器、重启交换机、修改端口和升级固件的高权限设备凭据。系统按“管理面安全系统”处理，不按普通展示站点处理。

主要威胁：

- 被盗账号执行危险操作；
- 设备凭据从数据库、日志、URL、设备配置备份、支持包或前端泄露；
- 通过管理地址发起 SSRF 访问宿主机/云元数据/其他网络；
- 操作重复提交或 Worker 重启造成重复重启/升级；
- 恶意固件、ISO、配置或日志文件导致路径穿越、磁盘耗尽或内容泄露；
- SSH/CLI 参数注入任意命令；
- 审计被修改后无法追责；
- 厂商设备使用弱 TLS、SNMPv2c 或 Telnet。

## 2. 认证

- 仅本地账号，不开放注册、OAuth 或默认匿名访问；
- 密码使用 Argon2id，参数在部署时按目标主机校准至单次约 250 ms，最低内存 64 MiB、迭代 3、并行度 1；
- 密码至少 12 位，拒绝用户名和常见泄露密码，管理员创建时要求首次登录修改；
- 连续 5 次失败锁定 15 分钟，锁定和解锁写审计；
- 会话使用 256 位随机 opaque token，PostgreSQL 保存权威哈希记录；
- Cookie：`HttpOnly`、`Secure`、`SameSite=Strict`、路径 `/`；
- 空闲 30 分钟、绝对 12 小时过期；修改密码、禁用用户或角色变化撤销现有会话；
- 所有变更请求要求每会话 CSRF token，登录和终端握手验证 Origin；
- 0.1.0 不把 JWT 存在 localStorage。

## 4. 危险操作保护

以下一律高风险：电源/重启/BMC 复位、端口和 PoE 开关、配置恢复、固件升级、虚拟介质挂载。

保护链：

1. 能力白名单与参数 schema；
2. 当前角色权限；
3. 设备就绪、在线和无冲突任务；
4. 当前密码复验，服务端会话记录最长 5 分钟有效的 `reauthenticated_at`，不向前端签发第二个 bearer token；
5. 服务端按 `contracts/operations.json` 生成操作计划与影响说明；
6. 用户输入设备名称；
7. 一次性、60 秒有效、绑定完整参数和设备版本的确认令牌；
8. `Idempotency-Key`、PostgreSQL 任务唯一约束和租约领取；
9. Worker 开始前二次校验并持久化 dispatch fence；
10. 设备维度互斥；
11. 明确回读验证或 `verification_required`；
12. 创建、开始、步骤、结果全程审计。

不提供批量危险操作、定时危险操作、自动重试或任意 CLI 执行 API。

## 5. 设备凭据

- 凭据只在设备探测、适配器会话和终端会话内短暂解密；
- 使用 AES-256-GCM 应用层加密，每条凭据独立随机 nonce；
- 主密钥从只读 Secret 文件挂载，不写入镜像、Compose 文件、数据库或日志；
- `key_version` 支持在线轮换：新写使用新密钥，后台重加密旧记录；
- AAD 绑定设备 ID、适配器键和凭据 schema 版本，防止密文跨设备替换；
- 密码/Token/SNMP key 永不回显；编辑表单只允许“保持不变”或“替换”；
- 设备账号应使用专用账号和最小厂商权限；不得复用个人管理员账号；

## 6. 设备 TLS 与弱协议

- 管理 HTTPS 默认验证证书；
- 自签名设备使用管理员确认的 SHA-256 证书指纹固定，不使用永久 `verify=false`；证书变化使设备进入 `tls_validation_failed`；
- 允许导入内部 CA；
- SNMPv3 为默认，SNMPv2c 需管理员显式选择并持续显示弱协议状态；
- Telnet 默认全局禁用，开启需管理员确认且只用于交互终端；自动化操作永不使用 Telnet；
- HTTP Web 管理地址允许打开但显示明文风险，不在平台中传递凭据；
- 所有协议弱化配置写安全审计。

## 7. 管理地址与 SSRF 防护

管理地址由管理员配置，但所有出站连接仍执行：

- 解析后只允许部署配置中的管理网 CIDR；
- 默认拒绝 loopback、link-local、multicast、broadcast、IPv6 link-local、容器网络、宿主机管理地址和 `169.254.169.254`；
- 每次连接使用解析后的 IP，防止 DNS rebinding；
- 重定向默认关闭；确需厂商重定向时只允许同一设备 IP/允许端口；
- 端口使用适配器白名单，不能由 API 参数请求任意端口；
- 虚拟介质 URL 由平台生成，设备访问范围独立配置，不能借此读取任意内部 URL。

设备拉取固件/虚拟介质使用专用签名票据，绑定设备来源 IP、文件、用途和有效期；来源 IP 只取服务端直接 socket 对端地址，不信任 `X-Forwarded-For`。该端点不能枚举文件、不能换取其他文件，也不接受用户提供的任意路径。票据从普通 URL 日志中脱敏，操作结束立即撤销。

## 8. CLI 与终端安全

- 自动化命令由驱动模板和严格类型参数生成，不接受用户自由文本命令；
- 接口 ID、文件名、版本号等使用适配器允许字符和设备发现白名单；
- 配置模式命令有明确进入/退出和错误检测，不靠提示符猜测成功；
- 浏览器终端使用一次性票据、来源校验、会话时限和并发限制；
- 终端 WebSocket 禁止跨用户复用；后端关闭时显式终止设备连接；
- 0.1.0 不记录终端正文，也不提供开启正文录制的产品开关。

## 9. 文件安全

- 上传文件名只作显示，存储名由内容散列生成；禁止路径拼接和符号链接；
- 流式上传并在写入前检查配额，超过声明大小立即中止；
- 计算 SHA-256、识别 MIME/魔数、检查类型与用途；扩展名不作为唯一依据；
- 上传目录不可执行、不可由 Nginx 直接访问；
- 固件/ISO 不在应用宿主机执行或挂载；
- 配置备份和支持包使用 AES-GCM 文件密钥加密，文件密钥由主密钥包裹；
- 下载使用 `Content-Disposition: attachment`、`nosniff` 和严格权限；
- 固件升级前适配器校验设备型号、版本、包元数据和 SHA-256；无法验证签名时在预览中明确提示；
- 物理清理前检查任务引用并写审计。

## 10. Web/API 安全

- Nginx 强制 HTTPS，生产启用 HSTS；
- CSP 默认 `default-src 'self'`，厂商管理页在新标签页打开，不嵌入 iframe；
- 设置 `frame-ancestors 'none'`、`X-Content-Type-Options: nosniff`、严格 Referrer-Policy；
- API CORS 生产关闭，开发只允许显式本地源；
- 输入使用 Pydantic 严格 schema，未知字段默认拒绝；
- SQL 只通过参数化 ORM/Core；
- 错误不返回堆栈、SQL、设备凭据或完整厂商响应；
- 日志脱敏器覆盖 password、token、authorization、community、auth_key、privacy_key、cookie、secret；
- 依赖锁文件、SBOM、漏洞扫描和许可证检查作为发布门禁。

## 11. PostgreSQL 与容器

- PostgreSQL 只绑定 Compose 内部网络；
- PostgreSQL 使用独立应用和迁移账号；应用账号无建库/超级用户权限；
- 容器默认非 root、只读根文件系统、删除多余 capabilities、设置资源限制；
- 仅 Nginx 暴露 Web 端口，event-ingest 暴露受限 UDP/TCP 端口；
- 镜像使用 digest 固定并生成 SBOM；生产不在启动时联网拉依赖。

## 12. 审计与不可抵赖边界

审计记录登录、用户/设备配置、凭据替换、安全配置、文件、终端会话和所有硬件操作。审计内容包含“谁、何时、从哪里、对什么、做什么、结果如何”，但不包含秘密和终端正文。

`audit_logs` 在应用权限层只追加，并限制数据库应用账号的更新/删除权限。0.1.0 不建设散列链、独立链头、数字签名或外部见证，也不声称在数据库/主机管理员对抗场景下不可抵赖。

## 13. 安全验收

- 无权限用户无法通过直接 API 调用执行任何操作；
- 重放确认令牌、幂等键或终端票据不能产生第二次执行；
- 数据库、日志、浏览器存储和 API 响应中找不到明文设备密码；
- SSRF 用例无法访问回环、link-local、宿主机和非允许 CIDR；
- 恶意文件名、超配额文件、错误魔数和路径穿越被拒绝；
- CLI 参数注入和未发现接口 ID 被拒绝；
- Worker/API 重启不会导致危险操作自动重放；
- Telnet/SNMPv2c/TLS 指纹变化均有明确告警和审计；
- OWASP ASVS 相关认证、会话、访问控制和输入校验用例通过。
