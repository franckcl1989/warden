# Warden 0.1.0 前端界面规范

状态：`APPROVED_BASELINE`

## 1. 设计目标

界面首先服务于“快速发现硬件问题、准确理解状态、安全执行原始操作”。视觉设计不得为了大屏效果牺牲表格密度、时间、单位、错误原因和操作证据。

0.1.0 是桌面管理界面：以 1440×900 为设计基准，支持宽度 1280 以上；1024–1279 可收起侧栏，低于 1024 显示只读浏览提示，不保证危险操作表单可用。不开发移动端专用布局。

## 2. 全局框架

```text
┌─────────────────────────────────────────────────────────────┐
│ Warden  | 当前系统状态                  用户 / 会话 / 退出   │
├──────────────┬──────────────────────────────────────────────┤
│ 总览         │ 面包屑 / 页面标题 / 数据时间 / 页面操作      │
│ 设备         ├──────────────────────────────────────────────┤
│ 当前问题     │                                              │
│ 操作任务     │                页面内容                      │
│ 文件         │                                              │
│ 审计         │                                              │
│ 用户与角色   │                                              │
│ 系统状态     │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 左侧导航固定宽 224 px，可收起至 64 px；
- 用户与角色、审计和系统状态仅管理员可见；不提供可扩展的通用“设置中心”导航；
- 顶栏显示系统依赖严重状态，但不显示外部通知中心；
- 内容最大宽度不限制，设备端口表利用可用宽度；
- 页面级筛选写入 URL query，刷新和分享内部链接后保持；
- 详情页 ID 在 URL，选中页签也写入 query/hash。

## 3. 状态视觉语义

颜色永远配合文字和图标，不单独承担含义。

| 语义 | 颜色用途 | 文案示例 |
| --- | --- | --- |
| 健康/成功 | 绿色 | 健康、在线、成功 |
| 警告/数据过期 | 琥珀色 | 警告、数据过期、弱协议 |
| 严重/失败 | 红色 | 严重、离线、失败 |
| 运行中 | 蓝色 | 采集中、执行中、等待设备 |
| 未知/停用/不支持 | 灰色 | 未知、已停用、不支持 |
| 待核验 | 紫色 | 结果待核验 |

可达性和健康使用两个独立徽标。例如“离线 · 最后健康”，禁止合并成“异常”。时间后显示数据新鲜度。

## 4. 通用组件

前端建立业务组件层，不在页面散用 Element Plus 原始组件：

- `DeviceIdentity`：名称、类别、厂商/型号、管理地址；
- `ReachabilityBadge`、`HealthBadge`、`FreshnessBadge`；
- `CapabilityButton`：能力状态、权限、禁用原因和需求编号；
- `MetricValue`：值、单位、质量和观测时间；
- `MetricChart`：统一时间轴、单位、空洞和质量提示；
- `ComponentTable`：组件当前态与分页/筛选；
- `EventTimeline`：设备事件；
- `OperationState`、`OperationTimeline`；
- `RiskPreview`、`DeviceNameConfirmation`；
- `SensitiveFileLink`；
- `AsyncState`：loading/empty/error/permission_denied；
- `ErrorDetail`：稳定错误码、用户说明、请求 ID 和可行处理。

组件属性使用 OpenAPI 生成类型，禁止复制一套近似状态枚举。

## 5. 列表规范

- 默认 20 条/页，可选 50/100；
- 首列为稳定名称，状态列固定，不隐藏最近采集时间；
- 筛选条件采用明确枚举，不以颜色过滤；
- 排序由服务端完成；
- 大端口/组件列表使用虚拟滚动或分页，不一次渲染全部历史；
- 表格横向滚动时名称和关键状态固定；
- 空列表区分“尚未添加”“筛选无结果”“无权限”“加载失败”；
- 设备列表只提供详情/编辑入口，不提供重启、关机等快捷危险按钮。

## 6. 总览规范

- 第一行只放可达性、健康、严重当前问题和未完成任务；
- 设备类型摘要最多四张卡，与四类原始设备一致；
- 需要关注列表按服务端优先级展示，不人为拖动排序；
- 最近任务显示真实任务状态，不用动画假定完成；
- 所有统计显示“截至时间”；SSE 更新后卡片轻量刷新；
- 不放机房地图、机柜图、采购金额、容量预测或外部通知。

## 7. 设备详情规范

### 7.1 头部

左侧显示设备身份；中部独立显示可达性、健康和数据时间；右侧只放“连接/操作”菜单和管理员编辑入口。离线时保留最后已知值并加过期遮罩，不清零为正常。

### 7.2 页签

页签按 `PRODUCT_DESIGN.md` 的四类设备固定。无支持数据的页签保留并显示“不支持及原因”，不完全隐藏原始需求，便于验收。

### 7.3 指标与图表

- 当前值显示单位、观测时间、质量；
- 温度 °C、功率 W、光功率 dBm、流量 bit/s、容量使用率 %；
- 图表时间范围默认 24 小时，可选 1h/6h/24h/7d/30d/180d；
- 7 天以内使用原始点，30 天使用 5 分钟聚合，180 天使用 1 小时聚合；界面显示实际分辨率；
- 数据缺口保持空白，禁止用上一值连线冒充；
- 不为数值曲线发明 warning/critical 参考线；设备提供的原始参考范围如需展示必须标注为设备信息，不能转成平台告警；
- 多组件默认显示异常或用户选择的最多 8 条，避免 48 端口图表失控。
- 不支持单独显示能力原因；尚无数据使用 `unknown`；数据过期使用 `stale/expired`。三者不得共用一个“暂无数据”。

## 8. 操作交互规范

- 能力按钮旁显示来源需求编号，悬停显示适配路径和禁用原因；
- 点击后先打开操作预览，不直接执行；
- 预览明确显示设备名称、动作、参数、影响、步骤、超时和验证方法；
- 高风险动作若最近 5 分钟未复验密码，先完成复验，再签发预览令牌；
- 高风险确认框的提交按钮在设备名称完全匹配前禁用；
- 提交后立即进入任务详情，不用临时 toast 作为唯一反馈；
- 任务时间线区分“平台已接收”“已发送设备”“等待设备”“验证”“终态”；
- `verification_required` 使用独立紫色状态，页面提供“重新回读”而不是“重试操作”；
- 终态失败展示稳定错误、失败步骤、可行处理和请求/审计 ID；
- 页面刷新后从服务端恢复任务，不依赖前端内存计时。

## 9. 文件规范

- 上传前选择用途，文件类型决定大小和权限；
- 大文件显示服务端已接收字节和 SHA-256 计算阶段；
- 文件 ready 前不能在操作表单选择；
- 固件/ISO 列表显示文件名、大小、SHA-256、上传者、时间和引用任务；
- 配置备份/支持包只对有下载权限的角色显示下载按钮；
- 删除需要二次确认并展示引用关系；运行中任务引用时按钮禁用。

## 10. 表单与错误

- 表单保存按钮只在本地格式通过后启用，服务端仍做完整验证；
- 设备连接测试按网络、TLS/协议、认证、身份、能力五阶段展示；
- 敏感字段编辑只显示空输入和“保持原值”开关，不显示掩码长度；
- TLS 指纹首次确认显示完整 SHA-256 和设备地址；
- 错误信息包含用户能做的下一步，不泄露堆栈/秘密；
- 全局 toast 只用于短暂确认，重要错误和任务结果必须留在页面中。

## 11. 加载、刷新和并发

- 首次页面加载使用骨架屏，局部刷新不清空旧数据；
- 旧数据保留时必须显示刷新中和旧数据时间；
- `If-Match` 冲突显示“配置已被其他用户修改”，加载差异后重新编辑；
- SSE 断开显示非阻塞连接状态并退化为 15 秒轮询；
- 恢复 SSE 后停止轮询；
- 浏览器离线时禁止提交操作，已提交任务仍在服务端执行。

## 12. 权限与可访问性

- 无权限操作不显示；能力不支持则显示禁用状态和原因，两者不得混淆；
- 所有按钮、页签、表格和对话框支持键盘操作；
- 状态图标有可读 label；
- 焦点顺序与视觉顺序一致；
- 高风险确认对话框不能通过 Enter 意外提交；
- 图表提供当前值/最值的文本摘要；
- 基本目标为 WCAG 2.1 AA 对比度。

## 13. 前端验收

- 四类设备在正常、离线、警告、严重、未知、不支持、未配置、过期场景均有视觉快照；
- 51 条需求在界面上有可定位展示/操作位置；
- 观察员看不到操作入口，管理员也不能绕过危险确认；
- 不存在机房/机柜、工单、通知等超范围导航；
- Chrome/Edge 1280 与 1440 宽度主流程通过；
- Playwright 与可访问性检查通过，状态文案与 `GLOSSARY.md` 一致。
