# Warden 0.1.0 项目规格

状态：`APPROVED_BASELINE`  
原始需求来源：[飞书《边端硬件监控及功能实现项》](https://yikongzhijia.feishu.cn/wiki/Y84PwLxSIiAlxGk15m8cEBWRn7d?fromScene=spaceOverview)

## 1. 产品目标

实现一个前后端分离、在内网私有化部署的 Web 系统，对一个小型私有化机房内的服务器、群晖 NAS、核心交换机和接入交换机进行统一监控与人工运维。

## 2. 0.1.0 原始业务范围

以下条目逐项转录自飞书文档，并于 2026-09-01 重新通过页面原表复核；逐字语义快照见 `SOURCE_BASELINE.md`。编号是后续设计、代码、API 和测试的唯一追踪标识。

### 2.1 服务器

适配对象：戴尔 iDRAC、浪潮 iBMC、超聚变 xFusion iBMC、联想 XCC、华为 iBMC。

监控需求：

- `SRV-MON-01` 整机综合健康状态（Health/告警灯）。
- `SRV-MON-02` CPU、内存、进风口、主板温度。
- `SRV-MON-03` 内存 ECC 错误、内存条故障。
- `SRV-MON-04` 硬盘状态、S.M.A.R.T、RAID 降级/失效、预故障（Predictive Failure）。
- `SRV-MON-05` 双电源在位/故障/负载、电压。
- `SRV-MON-06` 风扇转速及过低告警。
- `SRV-MON-07` 机箱入侵、面板告警灯。
- `SRV-MON-08` SEL 系统事件日志中的部件故障。

人工操作需求：

- `SRV-ACT-01` 远程管理卡冷复位。
- `SRV-ACT-02` 远程开机、关机、强制重启（Power On/Off/Cycle）。
- `SRV-ACT-03` 远程 KVM 控制台连接。
- `SRV-ACT-04` 一键采集 TSR 技术支持报告、SEL、系统日志并打包。
- `SRV-ACT-05` 远程挂载虚拟介质（ISO/USB）。
- `SRV-ACT-06` 固件版本查询与升级。
- `SRV-ACT-07` 资产信息查询（序列号/FRU 部件）。

### 2.2 群晖 NAS

适配型号：DS224+、DS225+。

监控需求：

- `NAS-MON-01` 磁盘 S.M.A.R.T 健康、坏扇区、磁盘损毁/降级。
- `NAS-MON-02` 存储池/RAID 状态（降级、重建中）。
- `NAS-MON-03` 系统温度、风扇转速、电源状态。
- `NAS-MON-04` 存储空间使用率（卷/共享文件夹）。
- `NAS-MON-05` UPS 联动状态。
- `NAS-MON-06` 系统日志、网络连通性。

人工操作需求：

- `NAS-ACT-01` 远程重启/关机。
- `NAS-ACT-02` 远程连接 DSM Web 管理界面。
- `NAS-ACT-03` 一键采集日志中心/技术支持报告。
- `NAS-ACT-04` 执行 S.M.A.R.T 快速/完整检测。
- `NAS-ACT-05` 查看快照/备份任务状态。
- `NAS-ACT-06` 固件升级、SNMP 告警配置。

### 2.3 核心交换机

适配型号：CloudEngine S5732-H48XUM2CC（原文 `s5732-h48xum2cc`）、S5731S-S48P4X-A。

监控需求：

- `CORE-MON-01` CPU/内存利用率。
- `CORE-MON-02` 端口 up/down 状态、流量、CRC 错误包、丢包。
- `CORE-MON-03` 光模块收发光功率、温度、电压、电流。
- `CORE-MON-04` 双电源在位/故障、风扇转速、整机温度。
- `CORE-MON-05` 环路检测、广播风暴、STP 状态。
- `CORE-MON-06` 端口震荡、设备重启、认证失败等关键日志。

人工操作需求：

- `CORE-ACT-01` 远程重启交换机。
- `CORE-ACT-02` 端口远程开启/关闭（shutdown/undo shutdown）。
- `CORE-ACT-03` 远程连接 SSH/Telnet/Web 网管。
- `CORE-ACT-04` 一键采集 `display diagnostic-information`。
- `CORE-ACT-05` 配置备份/恢复。
- `CORE-ACT-06` 查询光模块诊断信息。
- `CORE-ACT-07` 固件升级。

### 2.4 接入交换机

适配型号：S5735-L48P4S-A1。

监控需求：

- `ACCESS-MON-01` CPU/内存利用率。
- `ACCESS-MON-02` 端口状态、流量、错误包。
- `ACCESS-MON-03` PoE 供电状态、单端口功耗、总功耗告警。
- `ACCESS-MON-04` 电源、风扇、温度。
- `ACCESS-MON-05` 上联口光模块功率。

人工操作需求：

- `ACCESS-ACT-01` 远程重启。
- `ACCESS-ACT-02` 端口开启/关闭。
- `ACCESS-ACT-03` PoE 端口远程通断电，用于重启下联终端/摄像头/AP。
- `ACCESS-ACT-04` 远程连接 SSH/Web。
- `ACCESS-ACT-05` 一键采集日志、配置备份/恢复。
- `ACCESS-ACT-06` 固件升级。

## 3. 必要平台支撑范围

这些不是新增硬件业务能力，只用于安全、可靠地承载第 2 节：

- 本地用户登录和管理员、运维员、观察员三类最小角色权限；
- 添加、编辑、启用、停用设备以及连接测试；
- 设备凭据加密保存和轮换；
- 设备列表、设备详情、监控历史和设备事件展示；
- 基于设备明确上报的当前健康/故障/告警状态以及离线、数据过期的当前问题展示；设备日志保持事件历史，不自动升级为当前告警；
- 持久化操作任务、进度、结果和失败原因；
- 固件、ISO、配置备份和支持日志所需的受控文件存储；
- 所有人工操作的审计记录；
- 采集、持久化任务执行、协议接收和必要的系统运行状态展示。

平台支撑不得产生第 2 节之外的新硬件操作。

任何平台支撑必须同时通过三项必要性检查：能指出缺少它会使哪类第 2 节需求无法安全完成；不产生独立于设备监控/操作的新业务对象或工作流；能用部署配置解决的事项不得再建设产品页面和业务 API。认证、任务、文件和审计只围绕设备及来源能力存在，不能演变为通用身份平台、任务编排器、文件中心或合规平台。

功能项拆成多个实现动作时必须仍绑定同一原始编号。服务器电源条目的“强制重启/Power Cycle”只有一个统一动作 `power.cycle`；虚拟介质卸载仅作为挂载条目的安全收尾，不形成新的来源需求。

## 4. 明确不在 0.1.0 范围

- 机房、机柜、U 位、组织、租户或地域建模；
- 通用 CMDB、采购、库存、维保、合同或折旧；
- 工单、值班、告警确认/派单流程；
- 用户自定义告警规则、无设备依据的 CPU/容量/计数器阈值和通用监控规则引擎；
- 邮件、短信、电话、企业微信等外部通知；
- 自动修复、定时重启、批量危险操作或工作流编排；
- 公有云托管、跨站点管理、Kubernetes、高可用集群；
- 应用内数据库备份、PITR、灾备编排、备份页面和 RPO/RTO 承诺；交换机配置备份/恢复仍属于原始硬件功能，不受此项排除；
- 产品化采集参数编辑页、Prometheus 指标导出接口和与原始硬件能力无关的系统运维控制台；采集周期、接收端口等由部署配置管理；
- 移动 App、微信小程序；
- 飞书矩阵没有列出的其他设备类型或硬件操作。

## 5. 设计规模与运行假设

这些是工程运行假设，不是新增业务需求：

- 只支持单套小型私有部署，不在产品中实现设备数量授权或固定上限；
- 设备数、组件数、活跃序列数、同时在线用户数和保留周期必须在现场清单明确后形成该部署的验收负载；设计阶段不得凭空把某个数量写成产品承诺；
- 管理平台与设备管理口网络互通；
- 生产环境使用 HTTPS；设备侧优先 HTTPS、SNMPv3、SSH；
- 设备时间已通过 NTP 校准；平台内部时间统一存 UTC，界面按 Asia/Shanghai 展示；
- 支持近两代 Chrome 和 Edge，不支持 IE；
- 生产运行不依赖公网或云服务。

## 6. 质量目标

- 正常采集周期内，设备状态变化在 2 分钟内出现在界面；
- 人工操作在接收后 2 秒内形成可查询的持久化任务；
- 操作结果不得只依赖 HTTP/CLI 返回成功，能够回读验证时必须回读；
- 采集失败、凭据错误、设备不支持和结果不确定必须使用不同状态表达；
- API 读取类请求在该部署已声明的验收负载下 P95 小于 500 ms（不含直接设备交互）；
- 系统重启后未完成任务可恢复为可解释状态，不得静默丢失；
- 所有第 2 节需求均须通过 `TRACEABILITY.md` 指向验收证据。

## 7. 版本验收原则

0.1.0 只有在以下条件全部满足时可发布：

- 51 条原始需求全部具备代码、API、界面和测试追踪；
- 每个目标厂商/型号完成能力发现并形成兼容性记录；
- 有副作用的能力在真机或用户认可的等价实验环境完成验收；
- 不支持的能力如实标记并给出设备/固件证据，不能以占位按钮视为完成；
- 安全、离线安装、兼容升级和故障注入门禁通过；
- 文档与实际 OpenAPI、数据库迁移和部署清单一致。
