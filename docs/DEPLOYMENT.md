# Warden 0.1.0 私有化部署与运维

状态：`APPROVED_BASELINE`

## 1. 部署模型

0.1.0 只支持单台 Linux 主机上的 Docker Compose。所有服务使用预构建镜像，生产主机不编译代码、不联网安装依赖。

安装环境最低 4 vCPU、8 GiB RAM 和 100 GiB 可用 SSD，用于启动和功能验证，不代表生产容量承诺。生产资源必须在接入现场设备后，根据实际设备/端口/组件、活跃指标序列、采集周期、保留周期和文件需求运行容量基准后确定；数据库卷与固件/ISO/支持包文件卷分别估算。还需：

- 稳定的管理网络；
- 已配置 NTP；
- Docker Engine 和 Compose v2。

## 2. Compose 服务

| 服务 | 副本 | 说明 |
| --- | ---: | --- |
| `nginx` | 1 | 唯一 Web 入口、TLS、静态资源 |
| `api` | 1 | FastAPI，0.1.0 默认单进程以简化 WS 会话 |
| `worker` | 1 | 调度、采集、操作和维护；采集/操作独立并发池 |
| `event-ingest` | 1 | SNMP Trap/Syslog 接收 |
| `postgres` | 1 | PostgreSQL 18 当前小版本 |
| `migrate` | 按发布运行 | 一次性 Alembic 迁移 |

CPU/内存限制由现场验收负载确定并写入该部署的 Compose override。禁止通过盲目增加 Worker 并发压垮设备管理卡。

## 3. 网络与端口

宿主机默认只开放：

- TCP 443：Web/API/SSE/WebSocket；
- TCP 80：可选，仅重定向到 443；
- UDP 162：SNMP Trap，映射到 event-ingest 非特权端口；
- UDP/TCP 514：Syslog，按实际设备配置启用；
- SSH 管理端口仅对主机管理员网开放，与 Warden 应用无关。

PostgreSQL 5432、API 内部端口和文件卷不发布到宿主机网络。

出站只允许到配置的设备管理网 CIDR及必要端口。部署必须明确 `WARDEN_ALLOWED_DEVICE_CIDRS`，没有配置时设备探测全部拒绝。

## 4. 持久化目录

```text
/srv/warden/
├─ postgres/          # PostgreSQL 数据
├─ files/             # 内容文件，应用控制访问
├─ tls/               # Nginx 证书，只读
└─ secrets/           # 主密钥、数据库密码和会话 secret，只读
```

目录所有者使用专用系统账号；权限默认 0700，TLS 公钥可 0750。文件卷和数据库卷禁止由 Nginx 挂载。

## 5. 配置与 Secret

非秘密配置使用只读环境文件，Secret 使用 Docker secret 风格的文件挂载。必须配置：

- 应用环境、公开 URL、时区显示；
- PostgreSQL DSN；
- 凭据主密钥及版本；
- 文件加密主密钥；
- 会话签名/CSRF secret；
- 设备管理网允许 CIDR；
- 采集周期、分层保留期、Worker 采集/操作并发和文件配额；
- TLS 证书/私钥；
- Trap/Syslog 监听和对外地址；
- 虚拟介质由设备访问的平台基础 URL。

仓库只提交 `.env.example` 和 Secret 文件名，不提交实际值。启动检查发现默认密码、短密钥、缺失 CIDR 或生产 HTTP 时必须失败。

## 6. 首次安装

1. 验证主机时间、磁盘、Docker 和管理网路由；
2. 导入带 digest 的离线镜像包并验证签名/清单；
3. 创建目录、账号、TLS 和 Secret；
4. 填写非秘密配置并运行 `preflight`；
5. 启动 PostgreSQL，等待健康；
6. 运行一次性 `migrate`；
7. 启动 API/Worker/Ingest/Nginx；
8. 使用一次性引导命令创建首个管理员，初始密码不出现在命令历史；
9. 登录后立即修改密码；
10. 验证系统状态和一台测试设备的连接；
11. 禁用引导模式并保存安装报告。

引导命令只在没有用户时可执行；成功后再次运行必须拒绝。

## 7. 数据持久化边界

- PostgreSQL 和受控文件目录使用宿主机持久化卷，容器重建不得清空业务数据；
- PostgreSQL 是会话、任务、审计、设备、指标和短期 UI 事件的唯一权威数据源；
- 主密钥、数据库数据目录和文件卷的位置必须明确写入安装配置，启动时检查可写性和权限；
- 0.1.0 不提供数据库备份服务、PITR、灾备编排、备份页面、RPO/RTO 承诺或备份恢复发布门禁；如部署方需要基础设施备份，由其现有主机/存储策略负责，不属于 Warden 业务能力。

## 8. 升级与回滚

0.1.0 单机部署需要维护窗口：

1. 运行受控部署命令开启持久化维护模式，禁止新人工操作；
2. 等待运行中危险任务完成，不能强制中断固件/配置任务；
3. 导入新镜像和发布清单；
4. 运行兼容性检查和 `migrate`；
5. 依次重建后台服务、API、Nginx；
6. 执行冒烟、采集和只读真机检查；
7. 运行受控部署命令解除维护模式。

第 1/7 步使用仅宿主机管理员可运行的 `warden maintenance on|off` 命令更新 PostgreSQL 系统状态并写审计；Web API/UI 只读显示，不提供切换入口。维护模式开启后 API 拒绝新任务和 launch，已 dispatch 的任务继续执行/核验，监控读取和管理员查询保持可用。

0.1.x 迁移默认只允许向后兼容的 additive 变更。数据库迁移不自动 downgrade；如新版本包含不可逆或不兼容迁移，则该升级必须停止并另行形成版本决策，不能在 0.1.0 基线中虚构通用回滚能力。

## 9. 日常运维

### 9.1 每日检查

- 数据库和文件卷剩余空间；
- 采集成功率、离线设备和认证失败；
- PostgreSQL 中排队任务数量、领取延迟、超时和 `verification_required` 任务；
- Trap/Syslog 最近接收时间；
- TLS 证书和设备固定指纹变化。

### 9.2 容量阈值

- 磁盘使用 70% 警告、85% 严重；
- PostgreSQL 日分区未来至少预创建 14 天；
- 文件配额达到 80% 禁止新的大文件任务并提示清理；
- PostgreSQL 任务领取延迟超过两个采集周期时在系统状态页显示严重状态。

### 9.3 维护任务

- 每 5 分钟生成指标聚合；
- 每日创建未来分区并执行保留清理；
- 每日验证文件引用和审计记录写入连续性；
- 每周执行 PostgreSQL ANALYZE 和膨胀检查。

## 10. 无公网交付包

正式交付包含：

- 所有 OCI 镜像及 digest；
- 镜像签名/校验和、SBOM、许可证清单和漏洞报告；
- Compose、Nginx、配置模板和安装脚本；
- Alembic 迁移、OpenAPI、设计文档和发布说明；
- 设备兼容性/真机认证矩阵；
- 安装、升级、回滚边界和故障处理手册；
- 冒烟测试和验收脚本。

交付包在无公网测试环境完成一次全新安装和升级演练后才能发布。

## 11. 部署验收

- 仅预期端口在宿主机监听；
- 数据库和文件内容无法从管理网直接访问；
- 主机重启后服务自动恢复，危险任务不重复执行；
- 无公网条件下可安装和执行兼容升级；无法通用回滚的迁移边界明确；
- 现场声明的验收负载下资源、采集、任务领取和 API 达标；
- 设备管理网 CIDR 之外的探测被阻止并审计。
