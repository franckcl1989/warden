# Warden 0.1.0 风险登记

状态：`APPROVED_BASELINE`

风险不是已知限制的垃圾桶。每项风险必须有触发条件、缓解措施和发布关闭条件；不能用“存在风险”替代原始需求。

| ID | 风险 | 影响/概率 | 缓解措施 | 关闭或接受条件 |
| --- | --- | --- | --- | --- |
| `R-01` | 同类管理卡不同固件的 Redfish/OEM 字段和动作不同 | 高/高 | 标准 Redfish + 厂商 overlay；能力发现；按固件保存 fixture | 五种管理卡目标固件逐项真机认证，差异进入认证矩阵 |
| `R-02` | KVM、虚拟介质、TSR、固件升级依赖许可或厂商私有接口 | 高/高 | 探测许可/能力；不代理凭据；明确 unsupported/not_configured | 每厂商记录许可前提并实际进入 KVM、挂载介质、采集包、升级 |
| `R-03` | DSM WebAPI 随 DSM 版本和套件变化 | 高/中 | API 版本发现、会话封装、套件能力检查、脱敏 fixture | DS224+/DS225+ 目标 DSM 版本全矩阵认证 |
| `R-04` | Huawei VRP 版本、MIB、提示符和命令差异导致误判 | 高/高 | 型号/版本识别；版本化 MIB/命令模板；禁止自由命令；回读 | 三个型号目标 VRP 的监控、CLI 和升级真机认证 |
| `R-05` | 设备管理网不允许设备反向访问 Warden，影响虚拟介质/拉取固件 | 高/中 | 安装前双向连通 preflight；专用受限票据 URL；可选直传适配路径 | 目标 BMC 能从受控 URL 完成 Range 下载，防火墙规则归档 |
| `R-06` | 固件/配置恢复可造成长时间中断或设备不可用 | 高/中 | 包/型号/空间/哈希检查；维护窗口；单设备互斥；不自动重试；回读 | 非生产真机成功演练、失败前置校验演练和恢复手册通过 |
| `R-07` | 操作超时后实际仍在设备执行，重复提交扩大影响 | 高/中 | `verification_required`；幂等；回读；禁止终态直接 retry | Worker/网络故障注入证明不重放，人工核验流程通过 |
| `R-08` | 交换机端口指标数据量导致 PostgreSQL 增长和查询变慢 | 中/高 | `metric_latest`；状态变化点/6 小时检查点；分层保留；日分区；按现场活跃序列压测 | 现场验收负载下查询、聚合、清理和磁盘余量门禁通过 |
| `R-09` | 主密钥文件丢失或权限错误导致设备凭据和敏感文件不可用 | 高/低 | Secret 独立持久化挂载；启动校验存在性、权限和 key version；轮换前后做解密自检 | 主机/容器重启后仍能解密测试凭据与文件；缺失密钥时系统明确拒绝相关功能而不损坏数据 |
| `R-10` | 自签名证书、SNMPv2c、Telnet 降低管理面安全 | 高/中 | 指纹固定、内部 CA、SNMPv3 默认、Telnet 默认禁用、弱配置审计 | 所有弱协议均有显式批准和网络隔离；无永久 TLS 跳过 |
| `R-11` | 单机部署故障造成监控和管理暂时不可用 | 中/中 | Compose 自动重启、持久化卷、健康检查和离线安装包 | 主机/容器重启演练通过，数据卷未丢失；用户接受 0.1.0 无 HA |
| `R-12` | 缺少目标真机导致“模拟通过、现场失败” | 高/高 | 真机认证是发布硬门禁，experimental 不算正式支持 | 10 个目标适配对象全部取得维护窗口和认证报告 |
| `R-13` | 支持包、设备配置备份和终端包含密码或敏感拓扑 | 高/中 | 文件加密、最小下载权限、日志脱敏、终端正文默认不记录 | Secret 扫描和人工抽检通过，无明文凭据进入日志、配置备份或支持包 |
| `R-14` | SNMP Trap/Syslog 来源地址与管理地址不一致导致事件无法归属 | 中/中 | 连接配置允许受控附加事件源 IP；冲突源进入未归属隔离队列 | 每台交换机/NAS 发送测试事件并正确归属，冲突被拒绝 |
| `R-15` | 设备时间漂移导致事件顺序和审计不可靠 | 中/中 | 安装前 NTP；同时保存发生/接收时间；偏差状态标记 | 设备时间偏差小于 60 秒；异常时界面标记来源时间不可信 |
| `R-16` | DSM 管理功能和 Huawei 命令/MIB 缺少稳定公开参数文档，agent 可能凭抓包或其他型号资料猜实现 | 高/高 | 标记 vendor_private；精确型号/固件 API discovery；归档文档版本/MIB 散列；脱敏 fixture；真机契约测试 | 每个目标 DSM/VRP 版本的实际调用、失败码和回读均有可复核证据；无证据保持 experimental/unsupported |
| `R-17` | 现场设备/端口/保留期未明确时提前承诺固定容量，导致部署过大或不足 | 高/中 | 安装前生成验收负载；按实际发现序列测量 schema、索引、聚合、清理和文件增长；再给出资源建议 | 验收负载由用户确认，24 小时压测和增长外推满足该部署余量 |

## 风险处理规则

- `R-01..07`、`R-09`、`R-12`、`R-16..17` 未关闭时不得发布 0.1.0；
- 其余风险可以在缓解措施全部落地且用户书面接受残余影响后发布；
- 风险状态和证据在实现期维护于发布清单，不通过修改本文档偷换范围；
- 新发现的厂商/固件风险必须关联需求编号和认证报告。
