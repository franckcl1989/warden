# Warden 0.1.0 测试与验收策略

状态：`APPROVED_BASELINE`

## 1. 测试目标

测试要证明的不是“页面能打开”，而是每条原始设备需求在真实协议条件下正确展示或执行，并且失败、安全、重启和恢复语义可靠。

每条源需求有一个稳定测试套件 ID `T-{requirement_id}`；套件内按能力键和场景分 test case。没有追踪编号的测试不能单独证明需求完成，带 `A/B/C` 的临时编号不得作为跨层引用。

## 2. 测试层级

### 2.1 领域单元测试

覆盖：

- 可达性、健康、数据新鲜度和当前问题恢复；
- 任务状态机和非法转换；
- 权限、风险级别、确认令牌和幂等；
- 指标速率、计数器回绕和单位归一化；
- 文件引用、保留和配额；
- 错误分类与脱敏。

领域层分支覆盖率至少 90%，后端总体至少 80%，前端业务模块至少 80%。覆盖率不是发布的唯一条件。

### 2.2 数据库与迁移测试

- 在真实 PostgreSQL 18 容器运行，不用 SQLite 替代；
- 从空库执行全部迁移；
- 从上一个发布升级并校验数据；
- 验证唯一约束、操作互斥、任务行锁/租约、分区、保留和审计只追加；
- 并发提交验证幂等和乐观锁；
- 每个破坏性迁移执行升级前后校验 SQL。

### 2.3 API 契约测试

- OpenAPI schema 与实际响应一致；
- `capabilities/metrics/events/operations/alert-rules/http-api/error-codes/hardware-targets` 机器契约集合闭合，未知键、重复 profile、单位/风险/端点/支持目标漂移使 CI 失败；
- 成功、401、403、404、409、412、422、429、503；
- 未知字段、错误枚举、超大参数被拒绝；
- 凭据、Cookie、设备原始响应和堆栈不泄露；
- 所有 task channel 的 `*-ACT-*` 操作都必须经过 preview + confirm + idempotency；
- 所有高风险任务在会话未复验、复验过期、密码/角色变化或会话撤销后均被拒绝；launch 类能力按一次性票据契约测试，不误套任务确认流程；
- 没有需求编号的能力键不能提交；
- SSE 断线恢复和 reset；
- WebSocket 终端票据一次性、过期、跨用户拒绝。

### 2.4 适配器契约测试

所有适配器复用同一契约套件：

- `probe` 分阶段结果；
- `discover` 身份和能力状态；
- `collect` 返回单位、质量、时间和组件；
- 指标只使用 `contracts/metrics.json`，事件只写事件模型；不支持/缺值不得生成 0 或 normal 指标点；
- `plan_operation` 在禁止网络的快照环境生成风险、参数、互斥和超时；`preflight_operation` 覆盖实时状态通过/漂移/失败且不产生变更；
- `execute/verify` 的成功、明确失败、超时和结果不明；
- 厂商错误转换为稳定错误代码；
- 响应缺字段、未知枚举、分页、限流和大日志的鲁棒性。

厂商 fixture 必须来自脱敏真机响应或官方模拟器，保存来源型号/固件和采集日期。手工编造 fixture 只能用于单元边界，不能证明兼容。

### 2.5 协议模拟集成测试

测试环境提供：

- Redfish 模拟服务：标准资源、分页、异步 job、OEM 差异和错误注入；
- DSM 假服务：登录/session、磁盘/存储、任务、日志和升级 job；
- SNMP 模拟：标准/Huawei MIB、计数器回绕、Trap；
- Huawei VRP SSH 假设备：提示符、分页、配置模式、命令错误、断线和长诊断输出；
- Syslog 接收输入；
- 大文件上传、断点失败、哈希错误和空间不足。

模拟器用于可重复 CI，不替代真机认证。

### 2.6 前端组件与端到端测试

组件测试覆盖各状态、权限和错误；Playwright 端到端覆盖：

- 登录/过期/锁定；
- 添加设备、失败阶段、成功发现和启用；
- 四类设备详情各页签和指标；
- 设备不支持/未配置/暂不可用按钮状态；
- 低/中/高风险操作完整流程；
- 任务 SSE 更新和刷新后恢复；
- 文件上传/下载/引用冲突；
- 审计一致性；
- 没有机房/机柜/工单/通知等超范围入口。

浏览器覆盖当前 Chrome、Edge；关键页面通过键盘操作和基本可访问性扫描。

## 3. 故障与恢复测试

必须自动化或形成可重复脚本：

| 故障 | 期望 |
| --- | --- |
| 设备连接超时 | 采集退避；危险操作不自动重发 |
| 凭据错误 | 明确认证失败，停止高频重试，凭据不泄露 |
| 响应部分缺失 | 成功数据保留，批次 partial，缺失项有质量状态 |
| Worker 在读取中崩溃 | 租约过期后读取可重投 |
| Worker 在重启/升级后崩溃 | fence 前可重新领取；有副作用 profile 在 fence 后只回读/查 job；纯读取新 attempt 可恢复且不复用残缺产物 |
| API 重启 | 持久任务继续，SSE 重连 |
| PostgreSQL 不可用 | 新操作返回 503，不报告已接受 |
| 文件卷满/只读 | 禁止文件类任务，监控仍可读 |
| 宿主机重启 | 服务恢复，任务状态可解释 |
| 时间跳变 | UTC 时间和超时不产生重复任务 |

## 4. 安全测试

- RBAC 水平/垂直越权；
- CSRF、会话固定、Cookie 属性、Origin 验证；
- 暴力登录、锁定和会话撤销；
- SSRF：loopback、link-local、DNS rebinding、重定向、IPv6；
- SQL/CLI/路径/日志注入；
- 文件名穿越、符号链接、魔数伪造、超配额和压缩炸弹；
- 确认令牌篡改、过期、跨设备/用户复用；
- 密码复验状态缺失、过期、跨会话、密码/角色变化或撤销后复用；
- Idempotency-Key 并发重放；
- WebSocket 票据重放、跨 Origin 和并发限制；
- 设备文件票据跨设备/跨文件复用、来源 IP 伪造、过期、Range 越界和日志泄露；
- Secret 扫描、日志/API/设备配置备份/支持包明文凭据扫描；
- 依赖漏洞、镜像漏洞、SBOM 和许可证策略；
- 容器 root、capabilities、只读文件系统和网络暴露检查。

严重/高危已知漏洞在无书面风险接受时阻止发布。

## 5. 性能与容量测试

性能测试不再使用设计阶段虚构的固定设备配比。每个交付环境必须生成一份验收负载清单：实际/计划设备数、每类设备数、端口与组件数、发现后的活跃数值序列、采集周期、保留周期、同时在线用户和最大文件大小。测试数据至少覆盖该清单，并保留清单散列。

场景：

- 默认采集周期持续 24 小时，无队列无限增长；
- 按验收负载声明的并发用户浏览总览、设备和 24 小时趋势；
- 按声明上限并发执行低风险任务和不同设备的长操作；
- 按现场设备事件能力声明 Trap/Syslog 短时突发量；
- 按部署允许的最大虚拟介质流式上传，API 内存不随文件增长；
- 30 天等效指标数据下列表/趋势/保留任务性能。

门槛：

- 普通读取 API P95 < 500 ms、P99 < 1 s；
- 操作提交在 2 s 内持久化并返回 202；
- 调度延迟 P95 < 10 s；
- 设备状态变化在 2 分钟内可见；
- API/Worker 无持续内存增长；
- 数据库和文件磁盘增长符合基于该验收负载实测得出的容量估算 ±20%。

## 6. 真机认证

证据格式、覆盖粒度、条件状态和严格发布命令以 `HARDWARE_CERTIFICATION.md`、`contracts/hardware-targets.json`、`contracts/hardware-certification.schema.json` 为准；自由格式报告不能独立作为发布证据。

每个目标适配对象至少一台实际设备和一个主固件版本：

- Dell iDRAC；
- 浪潮 iBMC；
- xFusion iBMC；
- Lenovo XCC；
- Huawei iBMC；
- Synology DS224+；
- Synology DS225+；
- Huawei S5732-H48XUM2CC；
- Huawei S5731S-S48P4X-A；
- Huawei S5735-L48P4S-A1。

认证过程：

1. 记录型号、固件、许可和协议配置；
2. 执行能力发现并与设备原生界面/CLI 对照；
3. 对每个监控需求采集正常和可安全构造的异常证据；
4. 在维护窗口逐项执行人工操作；
5. 保存任务、回读、设备日志和审计证据；
6. 记录不支持、权限限制、重启时间和已知风险；
7. 对敏感 fixture 脱敏后加入契约测试。

服务器 KVM 认证必须实际进入可交互控制台；只打开通用 BMC 首页不算通过。虚拟介质和 Redfish 拉取固件必须验证设备能够通过受限票据读取目标文件，且票据在任务结束后失效。

电源、端口、PoE、配置恢复、固件升级、虚拟介质等测试必须使用非生产业务设备并获得维护窗口。固件升级至少验证一次成功和一种升级前校验失败，不通过人为中断设备电源模拟失败。

没有真机的厂商/型号不能标记“正式支持”；可以标记 `experimental`，但 0.1.0 正式发布门禁仍视为未完成。

## 7. 需求验收证据

每个 `target_id + requirement_id + capability_key` 认证记录必须链接：

- 自动化测试 ID 与最近结果；
- 适配器 fixture/模拟集成测试；
- 真机认证报告 ID；
- 对应 API/OpenAPI operationId；
- 对应前端路由/组件；
- 如不支持，设备/固件证据和用户认可的范围处理决定。

“有按钮”“有接口”“单元测试通过”任一项都不足以独立证明硬件能力完成。

## 8. CI 门禁

每个提交：格式、lint、类型、单元、数据库迁移、API 契约、前端组件、secret scan。

每个合并请求：上述全部 + 协议模拟集成 + Playwright 主路径 + OpenAPI/文档/追踪一致性。

发布候选：上述全部 + 按现场验收负载的 24 小时容量测试 + 安全扫描 + 离线安装/升级演练 + 逐能力真机回归矩阵严格校验 + SBOM/许可证/镜像签名。

## 9. 发布判定

发布负责人逐项核对 51 条原始需求，并运行真机矩阵严格门禁覆盖当前 306 个目标/能力组合。任何记录证据缺失、语义不一致、真机未认证或存在严重安全缺陷，0.1.0 均不可标记完成。不得用“后续补充”替代既定 0.1.0 范围；确需变更必须由用户明确调整原始版本范围并记录 ADR。
