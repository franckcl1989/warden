# 回滚边界（deployment/drills/ROLLBACK_BOUNDARIES.md）

> **本文档说明 0.1.x 可以回滚什么、不可以回滚什么；配套演练需 Docker 环境，尚未在本开发机执行（无 docker）。**
> 依据：`docs/DEPLOYMENT.md` §8（升级与回滚）、`docs/DATA_MODEL.md`（追加式审计/任务事件）、ADR-030
> （只追加审计与任务事件流豁免自动保留清理）、ADR-023（0.1.0 无备份服务/PITR/RPO-RTO，基础设施备份由部署方负责）。

## 1. 一句话边界

**0.1.x 是 additive-only 版本线：应用/数据库只做向后兼容的增量变更；没有自动 downgrade，没有通用回滚
能力；“回滚”在 0.1.x 里的正确含义是“部署回旧镜像”，而不是“数据库迁回旧结构”。**

## 2. 可以回滚的（代码/镜像层）

- 新 0.1.x 版本只含 additive 变更时，发布主机可把镜像与 Compose 回退到上一 0.1.x tag/digest：
  `docker load` 旧镜像 → 把 `WARDEN_IMAGE_*` 换回旧 digest → `warden preflight` → 按 `UPGRADE_DRILL.md`
  第 5 步顺序重建 worker/event-ingest → api → nginx。旧代码与 additive 新表/新列共存是安全的
  （additive 迁移的兼容性承诺即为此）；
- 升级窗口通过 `warden maintenance on|off` 管理，两个命令都幂等地写系统状态与审计（ADR-026）；
  随时可用 `warden maintenance off` 取消维护状态（不是回滚，是状态复原）。

## 3. 不可以回滚的（数据库/数据层）——如实陈述

- **迁移不自动 downgrade**：0.1.x 迁移没有运行时 downgrade 路径；`alembic downgrade` 不作为部署能力提供
  （DEPLOYMENT §8 末段：如新版本包含不可逆或不兼容迁移，升级必须停止并另行形成版本决策，不得虚构通用回滚）；
- **additive 新数据没有“撤回”**：新版本写入的数据（新表行、新列值、新事件/审计行）在旧代码下可能不可读或
  不被理解——**新代码写过的数据对旧代码不是降级安全的**，把镜像回退不会把数据“还原”；
- **audit_logs / operation_task_events 只追加，任何自动清理都不得执行**（ADR-030）：数据库触发器 +
  权限 REVOKE 双重只追加；0.1.0 保留清理跳过这两张表并记录 `skipped_append_only`；物理清理属于带外 DBA 操作。
  回滚演练不得以“清理测试数据”为由删除审计/任务事件行；
- **没有数据库备份/恢复服务**（ADR-023）：PostgreSQL 卷是唯一权威数据源；基础设施备份由部署方现有
  主机/存储策略负责。若部署方要“数据级回滚”，那是其备份策略的能力与责任，不是 Warden 能力；
- 一次性迁移容器 `migrate` 每次升级只前向执行一次；把旧 migrate 容器再跑一遍不会“撤销”新结构。

## 4. 发布门禁对回滚边界的约束（进入 0.1.x 发布的必要条件）

1. 发布说明（`docs/RELEASE_NOTES.md`）必须逐条列出该版本的迁移并声明 additive-only；
2. 任何破坏性/不可逆迁移（drop、数据重写、约束收紧后无法重建）在 0.1.x 内**禁止发布**——出现即停止并形成
   版本决策（0.2.0 或专门 ADR），`docs/DECISION_LOG.md` 记录；
3. 升级演练（`UPGRADE_DRILL.md`）第 4 步执行前核对本边界；不一致时停止升级；
4. 升级演练须验证“旧镜像 + 新 additive 结构”兼容启动（这正是 additive 承诺的真实验证）：
   ```bash
   # 演练可选步骤（在演练环境）：换回旧 digest 的 WARDEN_IMAGE_* → 重建 → /health/ready + 只读冒烟
   # 注意：只验证“旧代码可启动可读”，不是数据回滚；演练环境完成后丢弃重建
   ```

## 5. 升级前检查清单（与 UPGRADE_DRILL.md 第 0/4 步联动）

- [ ] 目标迁移全部 additive（无 drop/不可逆重写）；否则停止并走版本决策；
- [ ] 审计/任务事件表在目标版本仍只追加（无自动清理新逻辑）；否则停止；
- [ ] 升级窗口前已按部署方策略完成基础设施备份（如适用）；备份边界按 ADR-023 与部署方约定记录；
- [ ] 维护模式 on/off 均在演练环境验证并留有审计行证据；
- [ ] 回滚路径 = 旧镜像重建 + additive 兼容（上节第 4 条），已在演练环境验证。

回填区（发布主机执行后填写）：本次升级迁移清单核对结果 / 演练环境回退验证输出 / 决策记录引用。
